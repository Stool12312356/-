# -

Медиа-проект. Здесь живёт **только код** — крупные файлы хранятся локально и в Git не попадают.

## Зачем так

У воркспейса Arena лимит снапшота: **128 МБ / 10 000 файлов** на сессию.
При превышении платформа перестаёт сохранять изменения, и часть файлов теряется
между шагами (именно это и случилось: 558 МБ, 210 файлов, 95 файлов не сохранены).

Поэтому правило простое: **код — в репозиторий, медиа — вне репозитория**.

## Структура

```
.
├── src/          код, скрипты обработки — в Git
├── assets/       мелкие иконки/логотипы (<200 КБ каждый) — в Git
├── media/        видео, аудио, RAW, PSD, рендеры — в .gitignore, только локально
├── tools/
│   └── budget.sh проверка расхода бюджета снапшота
└── .gitignore
```

## Быстрая проверка бюджета

```bash
./tools/budget.sh          # объём и число файлов против лимита
./tools/budget.sh --top    # плюс 15 самых крупных файлов
```

Скрипт исключает то же, что и платформа: `node_modules/`, `dist/`, `build/`, `.venv/`,
`out/`, `target/`, `__pycache__/` и т.п. Эти папки бюджет не тратят.

## Правила, чтобы не повторить

1. **Коммит + push в GitHub** после каждого значимого шага. Репозиторий не считается
   в лимит снапшота и переживает сброс песочницы.
2. Крупные файлы — **во вложении в чат**, не в проект. Для работы я беру их из
   `/tmp/media-work` — этот путь в снапшот не попадает.
3. Перед добавлением файла в Git: если он больше ~5 МБ — он не должен быть в репозитории.
4. Не хранить в репозитории `.zip`/`.7z`/`.tar` — это самая частая причина перерасхода.
5. Git LFS здесь не поможет: LFS-объекты всё равно лежат в `.git` внутри воркспейса
   и считаются в снапшот.

## Восстановление проекта

Исходники есть локально у автора. По мере надобности файлы добавляются в `src/`
(мелкие — текстом) или загружаются в чат (крупные — через `/tmp/media-work`).
